## Start with a Post

A live blog belongs to a Post. The Post supplies its headline, summary and body,
public address, byline and publication workflow. Individual updates have their
own headlines, reporting, credits and permanent links.

1. Search **Posts** or **All content** for the assignment before creating another
   Post. Open the existing record, or create the Post you need.
2. Fill in **Headline**, **Summary**, **Post body** and the Post's credits. Confirm its public
   address and the person responsible for the first publication.
3. Open **Live updates** and select **Start live blog draft**. This adds a draft;
   it does not publish anything.
4. Keep **Coverage status** at **Ongoing**. For election coverage, choose
   **NJ Decides 2026** in **Coverage branding**. General coverage uses the regular
   live blog design. The election choice uses the shared NJ Decides artwork and
   its published appearance settings.

If you cannot start or edit the blog, check that you can edit and save this Post.
See [Access and roles](../access-and-roles/).

## Prepare the opening update

1. Select **Add update**. Keyboard and screen reader users hear **Add live update**;
   focus moves to **Update headline**.
2. Write a short headline and the update's reporting. Credit the people who
   reported that update under **Update byline**. Check inherited credits.
3. Add media through the update's media controls when it supports the reporting.
   Check alternative text, captions and credits. See
   [Metadata and media](../metadata-and-media/).
4. Mark **Key update** only for an update readers should find in the key-updates
   links. Add any other opening updates you need.
5. **Save** the Post. Wait for the save to finish before opening Preview or
   handing the record to someone else.

New updates appear first. Publication supplies their times and permanent links.
For a short detail under one update, use **Add follow-up** in that update. Write
up to 1,000 characters, check **Follow-up byline**, and save it with the Post.
Follow-ups use paragraphs, links, bold and italic and appear in a collapsible
thread under their update.

Use reporting and source attribution that will make sense to someone arriving
later through a link to one update.

## Preview and publish the first version

Open the saved Post's private **Preview**. Check the Post headline, summary and
body, election artwork when selected, update order, bylines, media,
key-update links and phone layout. Preview can show a working draft; the public
Post continues to show its last published version.

While the sitewide Election announcement is visible, it supplies the election
artwork. The band inside the live blog appears when that announcement is off or
expires.

The first publication uses the normal Post workflow: save, submit the saved
version for review, have it approved, then publish the approved version. Approval
alone does not publish. Follow
[Review, preview, and publish](../review-preview-and-publish/).

Open the public Post after publication and confirm the first updates and their
links. Share the public address, not the private preview address. Continue with
[Run a live blog](../run-live-blog/).

## Undo an accidental start

Before any update has been public, **Remove live blog** removes the blog from
the Post. Read the inline confirmation: “Remove the live blog from this Post?
Draft updates are deleted.” Select **Cancel** to keep it, or confirm removal and
save the Post. Starting and removing a blog before saving returns an otherwise
untouched Post to its original state.

If an empty blog is already public, publish the saved Post through the normal
review and publication workflow to remove it from the public page.

Once an update has been public, the removal action disappears. Published update
links stay available, including links to withdrawn updates. Use corrections,
withdrawals or **Ended** coverage instead of deleting the archive.

## Choose the appearance

In **Live blog appearance**, choose **Show reporter photos**, **Show reporter
cards** and **Playful style**. Photos and cards start on; playful style starts off.
These choices apply only to this live blog. Readers open details by selecting the
reporter photo, or the reporter name when photos are off. Keyboard readers focus
the control and press Enter or Space. Cards show a short public bio, the reporter’s
update count in this blog and a link to their published author page. On mobile,
the name appears above the time beside the photo; the card also shows the job title.
A public profile without a photo uses initials. Custom credits and reporters
without a published public profile use the PBS logo and have no card.

Check the notices beside update and follow-up bylines and before publishing. Boardwalk
warns when a reporter's profile is missing a photo, job title or bio, or is not
published. When you can edit the profile, its link opens the editor in a new tab
while keeping your draft open. Otherwise, ask a profile manager to complete it.
If your own profile is unpublished and self-service publication is paused, ask a
profile manager to publish it after you finish editing.
The notices never stop you from saving or publishing the live blog.
After a profile edit, save this draft and reload the Boardwalk tab to refresh the
profile notices.

Save and preview your choices, then publish them through the Post’s normal review
and approval workflow.
