---
title: Run a live blog
description: "Add updates, correct or withdraw reporting, manage reader updates, and pause or end coverage."
---

## Add reporting to the existing Post

Open the same Post for the whole assignment. Use **Live updates → Add update**,
write the headline and reporting, and check **Update byline** and any media.
Save, check the private Preview, and use the publication action your access permits.
A saved draft does not change the public blog.

Coordinate who edits the Post. If another person's save causes a version
conflict, keep your reporting, reload the current saved record and reconcile the
changes. Do not overwrite another person's updates. See
[Drafts, revisions, and recovery](../drafts-revisions-and-recovery/).

## Publish later updates

On an already public live blog, staff with Editor access can use
**Publish live updates now** for entries, follow-ups, corrections, withdrawals and coverage
status and appearance. This action does not need another approval. It requests publication;
the Post's publication status shows when the public site confirms the updates.
Check that status and open the public Post before treating an update as live.
If publication fails, keep your draft, read the error and follow any wait message
before trying again.

If the action is unavailable or disabled, read the reason shown in the panel.
Use the normal [review and publication workflow](../review-preview-and-publish/)
when your access requires it. The first live blog publication and changes to the
Post's **Headline**, **Summary**, **Post body**, lead media, public address or coverage
branding still need review and approval.

## Help readers follow the coverage

Readers see the newest updates first, with times in Eastern time. **Key update**
adds a link near the start of the blog. Each update's **Link to this update**
provides a permanent address; corrections keep that address and its place in the
archive.

The page checks for published entries about every 30 seconds while its tab is
visible. When entries are available, readers see a button such as **3 new
updates**. The screen reader name is **Load 3 new updates**, with a short polite
count announcement. The page stays in place until the reader chooses to load
them. The same filled button stays just below the site header while they read
farther down the blog. Loading moves focus to the newest new update and hides the button.

**Show 20 older updates** reveals the next group; its count shrinks for the last
group. Loading new entries
keeps already expanded older entries available. Without JavaScript, the full
published archive remains readable; reloading gets the latest published version.

## Add a follow-up

Open the update and choose **Add follow-up**. Write the short detail, check
**Follow-up byline**, then save, preview and publish with the same action you use
for updates. Use up to 1,000 characters in paragraphs, with links, bold or italic.
An update can have up to 20 follow-ups. They appear oldest first under that update.

Readers expand the follow-up count to read the thread. The link icon has the
accessible label **Copy link to this follow-up**. Its copied link opens that
follow-up’s thread directly. New and changed follow-ups arrive on open pages
without increasing the new-updates count or closing an open thread.

Editing a published follow-up needs a new **Follow-up correction explanation**.
To withdraw one, select **Withdraw follow-up in this draft** and explain why.
Save, preview and publish. Its link remains with the explanation; the original
reporting is removed. A published withdrawal cannot be undone. Unpublished
follow-ups can be removed after confirming the remove action.

## Correct an update

Open the published update inside **Live updates**. Make the correction and write
a new **Correction explanation** that tells readers what changed. Save, preview
and publish it. Readers see the current reporting, the explanation and an updated
time. The original publication time, position and permanent link stay.

Changing only a correction explanation does not create a new update. Readers who
already have the page open receive corrections with the next explicit load of
new entries or when they reload the Post.

## Withdraw reporting

Use **Withdraw update in this draft** on the published update. Fill in
**Withdrawal explanation** with the reason the reporting is being withdrawn.
Check Preview, then publish. The public update keeps its link and shows a
withdrawal notice in place of the reporting. A published withdrawal cannot be
turned back into the original report. Withdrawing an update also hides its whole
follow-up thread from readers. Its saved thread stays in Boardwalk's record for
audit, with editing and **Add follow-up** disabled.

For an update that has never been public, use its remove action and confirm
**Remove draft update**. This is different from withdrawing published reporting.

## Pause or end coverage

Set **Coverage status** to **Paused** for a break or **Ended** when coverage is
finished. Save and publish that change. Add a final update when readers need to
know what happens next or where to find continuing reporting.

Ending coverage keeps the archive, times, corrections and update links. A page
that observes ended coverage stops checking for new entries. Readers can still
open older updates and share their links. If an open page has no new entries to
load, reloading shows the latest coverage status.

For a new assignment, see [Create a live blog](../create-live-blog/).

## Change the appearance

Use **Live blog appearance** to turn **Show reporter photos**, **Show reporter
cards** or **Playful style** on or off for this blog. Photos and cards start on;
playful style starts off. Readers select the photo to open reporter details. With
photos off, the name opens the card. Keyboard readers focus the control and press
Enter or Space; Escape closes the card and returns focus. Cards show a short public
bio, the reporter’s update count in this blog and a published author-page link.
Mobile headers show the reporter name above the time; the job title stays in the
card. A public profile without a photo uses initials. Custom credits and reporters
without a published public profile use the PBS logo and have no card.
The first update on each New Jersey day shows the date with its time. A follow-up
shows its date when the day changes from the previous reply or its parent.

Boardwalk shows profile notices at update and follow-up bylines and before publishing.
Missing photos, job titles and bios, and unpublished profiles, need attention.
Open the linked profile editor in a new tab when you can edit it. Other notices
ask you to contact a profile manager. These are warnings: you can still save and use
**Publish live updates now**, including when profile details cannot be checked.
When self-service profile publication is paused, ask a profile manager to publish
your own profile after you finish editing it.
After a profile edit, save the live-blog draft and reload the Boardwalk tab to
refresh the profile notices.

Save and publish the Post to apply these choices. If you have Editor access or
above, **Publish live updates now** can publish appearance changes on an already
published live blog with the same permissions as coverage status. Open the public
Post after its publication status confirms the change.

## Put content beside live updates

In a live blog Post’s body, open a standalone plank’s **Settings** and change
**Destination** to **Live updates sidebar**. Use this for context, links, buttons
or other supporting content. Add and arrange planks with the existing controls.
Move a plank out of its span before choosing the sidebar destination.

On screens at least 1,024 pixels wide, updates use about two-thirds of the space
and the sidebar uses one-third. Smaller screens show the introduction, updates,
then sidebar. **Post body** puts the plank back above the updates. Existing
content stays where it is until you change its destination. Without a live blog,
sidebar planks render in the ordinary Post body. Their saved sidebar destinations
remain editable in Settings; choose **Post body** to clear a saved destination.

Readers can select an entry image to expand it, read its caption and credit, or
choose **Open full image** to open the original in a new tab. Escape or **Close
image** returns focus to the image link.
