## Area, Category and Origin

**Area** groups content for staff: Watch, Support, Station or Compliance. Accounts
with an access level use that level's site-wide capabilities. An account that
still uses area grants can have access limited to its named areas. Area does not
change public navigation or topics.
For a new Post, choose Area beside the title and summary. If only one area is
available, it is selected for a new Post. A saved record keeps its assigned area;
an unassigned Post draft can choose its first area before publication.

**Category** files media under labels such as General, Entertainment and Staff
profiles. Each category shows its description in the picker. The primary media
category still controls media access; additional categories help people find it.

**Origin** records where the media item came from: Site build, Uploaded or
Voiceover. Find it separately from categories in **File information** or the
image picker. **Source** still names a video library in Boardwalk.

## Understand the metadata groups

A page or post can separate metadata into groups such as **Basics**, **Search**,
and **Social sharing**.

### Basics

Basics identify the record for editors and readers. They can include:

- Working or public title.
- Summary or description.
- Author or byline.
- Dates.
- Area or assignment.
- Read-only public path.

For a Post, **Summary** is an optional deck that appears beneath the Post title. It
is also the preferred short description for listing cards and default page
metadata. **Excerpt** is a fallback for listings and default descriptions only
when Summary is empty. Excerpt does not appear beneath the Post title. Search and
Social descriptions remain separate overrides for their named contexts.

### Search

Search metadata helps search engines and site search describe the page. It can
include a search title and description that differ from the on-page headline
when clarity requires it.

For a Post, Search title uses the current Post title until you enter a custom title.
The inherited title changes with Post title. Select **Use post title** to remove a
custom override and resume inheritance.

### Social sharing

Social metadata controls how an approved page is described when shared. It can
include a social title, social description, and image.

For a Post, Social title also uses the current Post title until you enter a custom
title. Its override is independent from Search title. Changing or resetting one
does not change the other.

Do not fill every field with the same sentence automatically. Each field has a
different context, but all versions must describe the same underlying story or
service accurately.

## Keep the public path protected

Page routes can be read-only because they come from the route registry or
protected record identity. A Post can instead expose an editable **URL slug**
in **Post settings**. Leave it unchanged during a practice session.

Do not create a duplicate record to force a URL change. When a route must change:

1. Confirm the editorial and operational reason.
2. Check whether the existing public URL has already been published.
3. Escalate the route change to the role authorized to preserve redirects and
   canonical identity.
4. Verify both old and new addresses after release.

## Write useful titles and descriptions

A strong metadata title:

- Identifies the page or post without internal shorthand.
- Places the important subject early.
- Remains accurate outside the surrounding CMS.
- Avoids unsupported urgency or promotional claims.

A strong description:

- Explains what a visitor will find.
- Uses plain language.
- Completes the thought without depending on an image.
- Does not expose draft notes or workflow language.
- Remains consistent with the published content.

Read search and social fields as standalone copy before saving.

## Review media and give staff feedback

The common review and comments interface covers images, documents, videos, imported UGC, audio, episodes, and
packages in the Media library, including items opened from Favorites or
Collections. In the UGC queue, use **Open the library asset** after import. Pending and rejected submissions keep their existing decision workflow.

Open an item to see **Your review**. **More like this** and **Notes** belong to
your account. Only you can read them. Use the heart to add or remove your
private favorite. Notes accept up to 2,000 characters. Select **Save** in Asset
details, or **Save details** in the full-size viewer, for an image, document,
or audio review. Select **Save review** inside a video's
**Your review** section. If another session saved first, reload the saved review
before trying again. The reload keeps your draft so you can retry it against
the newer version.
The leave warning protects an unsaved review or comment draft.

**Staff comments** are separate from your private note. Staff with access to the
item can read them inside Boardwalk. Each comment shows its author and time.
You can edit or delete your own comments. A comment never appears on the public
site. Save comments explicitly, and confirm a deletion. If a save fails, keep
the draft and use the available reload or retry action.

### Select and act on images

Each image and document card has quick actions. Point at a card, or move to it
with the keyboard, to show its selection box, **Add to favorites**, **Add to
collection** and **More actions**. On phones the selection box and **More
actions** always show.

- Select a card's name or picture to open its details. Opening a card keeps any
  selection you already made.
- Select the box in a card's corner to select it without opening it. Hold
  Command (Mac) or Ctrl (Windows) and click a card to add or remove it, or hold
  Shift and click to select every card between. The selection carries across
  pages and filters, and a bar at the bottom of the results shows how many items
  are selected.
- With the keyboard, Tab reaches the cards once. Use the arrow keys to move
  between cards, Space to select, Shift and an arrow key to extend, and Enter to
  open. Command+A or Ctrl+A selects every card on this page; **Select this
  page** in the toolbar's **More actions** does the same without the keyboard.
  Escape clears the selection, then closes details, then clears the search.
- Right-click a card, or press Shift+F10, for the same actions as **More
  actions**: **Open details**, **Add to favorites**, **Add to collection**,
  **Select**, **Copy link** and **Delete from library**. **Delete from library**
  opens details at the confirmation, so nothing is deleted until you confirm.
- Rest the pointer on a card, or keep keyboard focus on it, for a moment to see
  its full name, type, size, category, update time and tags.

### Restore a deleted image

On **Images**, choose **More actions → Recycle bin** to see deleted images in categories you can manage. The list shows each thumbnail, name, category, the name of the staff member who deleted it (when your account can view users), or **A staff member**, deletion time and days remaining in its 30-day retention period. Images due for removal soonest come first. **Due for removal** means the deadline has arrived or passed. The removal deadline marks eligibility; it does not confirm that storage removal has run.

Choose **Restore** beside an image to return it to the active library. A success message confirms the restore. If a category is archived, restore the image's primary and assigned categories first. If the library is full, make room before trying again. If the image changed, choose **Refresh bin** and review it before retrying. **Being removed** means the image cannot be restored. There is no **Delete now** action in this view. PDFs and videos are outside this image bin.

If an upload in the Media library matches an existing file that cannot be opened in the active library, staff who can open the bin can choose **Find it in the Recycle bin**. The link keeps filters from Images only; uploads on other tabs open the bin without carried filters. Editor and post-template image pickers direct staff with bin access to the Media library's Recycle bin, so you can keep your editor open. If you cannot open the bin, ask a media manager to restore the image. Confirm leaving the upload form if you have unsaved changes. Restoring keeps the existing image's details; it does not apply the metadata entered for the refused upload.

### Preview with Quick Look

Choose **Quick Look** from a card's **More actions**, or focus the card and press
Command+Y on a Mac or Ctrl+Y on Windows. It opens a light preview without an
editing form. An image shows its largest available preview. An animated image
stays animated. A PDF shows its file mark and an **Open original** link.

Use Left and Right Arrow, or **Previous** and **Next**, to move through the
items on the loaded page. The counter shows your place. Quick Look does not
load the next item in advance. Press Escape or the same Quick Look shortcut,
click outside it, or move Tab past either end to close it. Focus returns to the
item that was on screen unless you clicked another control.

### Open an image full size

Choose **Open full size** from an image or document card's **More
actions**. You can also open details, move to the preview and press Enter. A
still or animated image loads its original file in the viewer. A PDF has no
page preview, so it shows a PDF mark and **Open original**.

The image viewer has **Fit**, **100%**, zoom controls and **Details**. Fit shows
the full preview. 100% shows the preview at its pixel size. Scroll the viewing
surface to pan a zoomed image; arrow keys scroll it while that surface has focus.
These controls change only your view of the image.

On a wide screen, Details opens beside the image. On a phone, Details fills the
work area until you select **Close image details**. Opening or closing Details
keeps your zoom, scroll position and unsaved fields. Document previews keep
Asset details below the preview on narrow screens.

Use **Previous file**, **Next file**, or Left and Right Arrow outside the image
controls to move through the loaded items. The counter shows your place. The
viewer stops at the first and last item and does not load the next one in advance.

On wide screens, **Save details** is in the viewer header. On phones, open
Details to use **Save details** and **Cancel changes**. Save or discard changes
before you move to another item. A successful save
keeps the current item open and refreshes the results once when you close the
viewer. Press Escape or select Close to return to the card for the item on
screen. If a saved change removes that item from the current filters, focus
moves to the next card, the previous card or the results heading, in that
order. The page tells you that the item no longer matches the view.

Select up to 100 images, then choose **Edit tags** from the selection
bar or a selected card's menu. The shared inspector opens with a preview made
from thumbnails already on the page. It keeps a fixed snapshot of the selection.

In **Details** and **Rights**, use each field's menu to leave description,
credit or license unchanged, set one value on every editable image, or clear the
field. Name, filename, alternative text and categories stay out of the batch.
An image that your role cannot edit is left out and named in the review.

In **Tags**, a solid token is on every image and a dashed token whose accessible
name includes "mixed" is on only some. Remove a mixed token to remove it where
present. Add a token to add it to all editable images. Matching ignores letter
case. Each resulting image can have 20 tags of up to 40 characters. The Tags
menu can replace or clear every tag and warns before existing tags are removed.

Select **Review N changes** to compare each before-and-after value. Nothing is
saved before **Apply to N images**. Saves run one image at a time. Unchanged
images are skipped, and a conflict is shown without an automatic retry. The
list refreshes once when you close the results. Opening and editing the
inspector and opening review make no additional request.

### Use the list layout

Choose **List** under **Layout** in **Display** to see results as rows. Each
row shows the name and a column for each fact Display shows on cards, plus
**Updated**, which the list always shows. Select the **Name**, **Size** or
**Updated** heading to sort by it; select it again to reverse the order. The
arrow shows which column sets the order. The box in the heading row selects or
clears every row on this page. On a phone, each row keeps its facts on a line
under the name.

Rows work the way cards do: select a name to open details, use a row's box to
select it, use the Up and Down arrow keys to move between rows, and right-click
a row or press Shift+F10 for its actions.

While asset details or an upload have unsaved changes, the card and row
controls wait until you save or discard them.

Do not download and re-upload an existing asset simply to make it easier to
find. Improve the existing metadata when your role permits it.

## Save personal media favorites

Select the heart on an image, document, audio, or private video card to save it
to your Boardwalk account. The heart does not open or choose the asset. The same
control appears in Asset details and the image picker. In the picker, selecting
the heart does not fill the editor field.

Open **Media library → Favorites** to review saved images, documents, audio,
and private videos together. **Type** shows Images, Documents, Audio, or Videos
on the current page. It does not search later pages. **Display** switches
between cards and rows. Select a card to open the full viewer; **Previous file**
and **Next file** move through the loaded mixed-media order without closing it.
**Quick Look** shows the available preview without opening the full file. The
viewer asks before closing or stepping away from unsaved metadata.

Select the filled heart to remove one favorite. Select several records to show
**Remove from favorites**, which accepts up to 100 records in one request. A
failed record stays selected and shows its own error; records that were removed
leave the page. **Add to collection** accepts up to 30 available records.
Selection can carry to another favorites page. **Select this page** selects
only the visible records. If an item is no longer available to your account,
it remains labeled **Unavailable favorite**. You can select or remove it, but
cannot open it or add it to a collection.

Favorites are personal to the signed-in CMS account. They do not change media
permissions or publish an asset. The heart on a voiceover is this shared media
favorite. Its **More like this** and **Notes** fields remain private review
choices and save only when you select **Save** in Asset details or **Save details**
in the full-size viewer. Wait for the heart
control to finish saving before closing the page. If a save fails, select the
same control again after the failure message appears. Use **Try again** when the
favorite list could not be loaded.

## Organize a media collection

Use the corner **Pin** toggle to keep a collection near the top. It is separate
from the card that opens the collection. **New collection** is the primary
action; **Upload** stays available in the workspace.

Use **Collections** for a fixed package of images, documents, audio, and private
videos. A collection saves references to existing files. It does not copy,
upload, publish, or change access to those files.

1. Open **Media library → Collections**, then select **New collection**.
2. Enter a name and optional description.
3. Choose **Only me** for a private collection, or **All active staff** for a
   collection that any approved active staff member can organize.
4. Create the collection. Use **Pin** to move it ahead of other collections
   after it is loaded in your own list.
5. Open **Images**, **Audio**, or a video source. Select up to 30 items. A bar
   with **Select this page** and **Add to collection** appears at the bottom of
   the results once an item is selected. To add one item, use **Add to
   collection** on its card instead. Select **Add to collection** and choose
   the destination. Add another source in a separate pass to build a mixed
   package.

Use **Filter** on the Collections list to show Active or Archived status and
Private or All staff scope. Scope applies only to collections already loaded
on this page. A pin stays ahead of other collections in the visible scope.
If a scope has no collections, choose **Clear scope** to see the other scope.

Open a collection to rename it, review items as cards or rows, or archive it.
Select up to 30 items and choose **Remove from collection** to remove their
references in one step. You can also remove one item from its menu. Removing a
reference does not delete or change the file. Use **Load more items** for the
next page. Quick Look and the full viewer follow the loaded collection order;
each file still requires its own access. To add an item, start in its source
library. Archiving preserves the collection and every file; choose Archived in
the Status filter to restore it. A private unavailable reference stays labeled
**Unavailable item** so its owner can remove it. It cannot open or preview.
Shared collections omit items that the current account cannot access.
If the item list reloads, the full viewer closes and the list starts at page 1.

A collection is a fixed list. It does not update automatically when new files
match a search. Its folder shape does not create nested folders or move files.
Collection membership does not grant file access. A voiceover can be added as
an Audio asset, but each person still needs access to its primary category and
must use authenticated playback.

## Caption a post's lead image

Open **Post settings → Hero image** and choose a **Lead image**. Use the optional
**Lead image caption** field for a description or photo credit beneath the image.
Keep **Lead image alt text** focused on what the image adds for someone who cannot
see it; the visible caption does not replace alt text.

The caption can contain more than one line and appears below the lead image in
each Post format. Select the information icon beside a field when you need its
specific guidance. Save and preview the Post to check the caption. Leaving it
blank displays no caption. Replacing or removing the lead image clears its
caption, so review the credit whenever you choose a different image. Content
templates preserve the caption with the image; layout-only templates omit both.

## Choose artwork for copied video stories

When a Post starts with a library video, its generated poster can appear on the
published Post. To keep artwork when copying the Post into a shelf, choose a
**Video poster** from the image library and publish the Post first, or choose
an image on the copied card. Home selections follow the published Post's image. If Home cannot show
that image in the editor, check the saved preview or choose a Home image.
The source Post can publish without a poster. A visible copied shelf card needs
an image before its shelf can publish.

## Add an image to a post

1. Open the assigned post and enter editing mode if needed.
2. In **Post body**, select **Add content** where the image belongs and choose
   an image block. For an existing image, select **Change image**.
3. Open the image picker, search for the approved asset, and select it.

4. Confirm the correct image appears in the block.
5. Write **Alt text** for what the image communicates in this story. Add a
   **Caption** when readers need more context. Check the asset's required credit.
6. Save the draft. Check the image, caption, and surrounding text in the saved
   draft and in a new preview when your workflow requires one.

A **Lead image**, **Hero background image**, and a body image are separate fields;
return to the field you intended to change.

## Set the focal point

Use these steps when the field offers the focal-point control, such as a profile
photograph. Other image fields may instead offer named crop positions.

<figure class="admin-docs-screenshot">
  <p class="admin-docs-image-note">Screenshot omitted from this source distribution.</p>
  <figcaption><strong>Keep the subject inside Crop preview.</strong> Click, tap, or drag the image. The arrow controls and keyboard provide the same adjustment without dragging. </figcaption>
</figure>

1. Select a point in the image to center the crop there, or drag to reposition.
2. Watch **Crop preview**. Keep the important subject inside it.
3. For keyboard control, focus **Image focal point** and use the arrow keys.
   Hold **Shift** with an arrow for a larger move. The visible direction buttons
   also work without dragging.
4. Use **Reset to center** to start again. **Escape** cancels an active drag;
   **Enter** on the image resets the position.
5. Save the enclosing profile or editor form. Check the resulting crop at the
   size readers will see.

**Check:** The original image is unchanged. If an axis cannot affect the crop,
its move buttons are disabled. Changing the preview alone does not save the form.

## Inspect an asset before use

Check:

- **Name:** clear enough to recognize later.
- **Description:** explains the asset beyond the filename.
- **Alternative text:** describes the informative visual content when the asset
  is used as an image.
- **Credit:** identifies the required source or creator.
- **License or usage note:** confirms that NJ PBS may use the asset as intended.
- **Tags and category:** support future discovery.
- **File kind and dimensions:** fit the destination.
- **Crop or focal point:** keeps the important subject visible in responsive
  layouts.

An image that looks correct is not automatically cleared for use.

## Write alternative text

Alternative text communicates the information a sighted reader receives from
the image.

The CMS does not stop a save or publish when alt text is empty. It shows a
warning under the field, and after you publish it tells you how many images
still have no alt text. Add the alt text as soon as you can, or mark the image
decorative. An image that is marked decorative must have empty alt text; the CMS
still stops a save when a decorative image also has a description.

Write it from the context of the page:

- Identify people when their identity matters and is known.
- Describe the meaningful action, setting, or visual evidence.
- Keep relevant visible text when it is not repeated nearby.
- Omit decorative details that do not help understand the content.
- Avoid “image of” or “photo of” unless the medium itself matters.
- Do not repeat a caption word for word.
- Do not use a filename, credit line, or keyword list as alternative text.

Example:

> New Jersey State House in Trenton seen across the lawn on a clear afternoon.

A decorative image should use the CMS's decorative treatment when one is
available, not an invented empty description that bypasses required editorial
review.

## Write credits and captions

A credit answers who created or supplied the asset. A caption explains what the
reader should know about it. They are not interchangeable.

- Preserve exact required credit language.
- Identify people, place, and date when editorial context requires them.
- Do not put copyright or licensing instructions into alternative text.
- Do not use the caption to compensate for inaccurate body copy.
- Check punctuation and link destinations.

## Upload an asset

Only upload when the media does not already exist and your role permits asset
management.

Select **Upload** in the toolbar. The upload sheet holds file intake and
details. Drop files on its Files area, into the Images results, or use its file
picker. **Upload** waits while asset details have unsaved changes; save or
discard them first. A tray at the lower right shows active work and completed
receipts. Closing the sheet keeps an active upload in the tray; it does not
stop the transfer. Use the tray's **Stop** or **Cancel** action if you need to
stop it. A browser reload does not recover selected local image files.

You can choose a video in the same control. Boardwalk stays on this page and
starts that video in **Videos**. When the video is ready, a
notice names that library and offers to open it. The Images upload sheet accepts
images and PDFs. Choose WAV files from **Audio**. The Audio upload sheet accepts
WAV files and directs other library types to Images. See
[Audio](/guide/voiceover-library/) for supported PCM formats and the 10 MiB limit.
Favorites and Collections have a general **Upload media** control. It sends
images, PDFs, and WAV files to their library and does not switch tabs. Files
that a control does not accept are named in the intake message; accepted files
continue.

Before upload:

1. Confirm usage rights.
2. Use the best available source file.
3. Choose a stable, descriptive filename.
4. Remove private metadata when policy requires it.
5. Confirm the file type and size are appropriate.
6. Prepare the title, description, alternative text, credit, license note, and
   tags when you know them.

For two or more selected files, select **Upload all files** to start the batch
with the current details. The CMS uploads each file in order. You can still
upload one file at a time. Staff with media management access can add or change
optional details in the media library after upload. Confirm usage rights before
upload, and select an authorized primary category for each file.

If the file is already in the media library, the CMS uses the existing file
and marks the upload as done. A warning names the existing file. The title,
alt text, and other details you entered for that upload are not saved. Open the
existing file to check or change its details. If the existing file is in a
category you cannot open, the upload stops. Ask an editor who can open that
category to use the existing file.

You can upload a file without a license. The CMS shows a warning, and the file
details show "No license entered" until you add one. Add the license as soon
as you know it, so the rights are on record.

After upload:

1. Wait for processing to finish.
2. Open the asset detail view.
3. Check the rendered preview.
4. Save complete metadata.
5. Search for the asset again to confirm it is discoverable.
6. Select it from the target record.
7. Preview the final crop when the workflow permits it.

Do not upload screenshots of text as a substitute for accessible text content.

## Replace or update an asset

Replacing an asset can affect more than the record currently open if the same
media item is reused.

Before replacing:

- Determine where the asset is used.
- Confirm whether the change is a correction or a new editorial image.
- Prefer a new asset when historical pages should retain the original.
- Preserve required credit and license information.
- Check crops at wide and narrow widths.

If you cannot determine the reuse impact, create a clearly named new asset and
ask the media owner to review the old one rather than silently changing it.

## Use documents safely

For PDF or document assets:

- Give the link clear purpose.
- Include the file type and, when helpful, approximate size.
- Ensure the document itself is accessible.
- Avoid publishing internal comments, tracked changes, hidden sheets, or
  personal information.
- Replace obsolete public documents through the approved retention process.

The CMS metadata cannot make an inaccessible source document accessible.

## Replace an image file

Open an uploaded image's details and choose **Replace file**. This action is available when you can manage media in the image's stored category. It is unavailable for videos, PDFs, items from Site build and items in the recycle bin. Save or discard unsaved metadata edits first.

Choose a JPEG, PNG, WebP, GIF or AVIF file, then confirm the replacement in the dialog. The dialog keeps the editor unavailable while replacement is in progress. **Optimize JPEG and PNG files and convert them to WebP** is on by default, as it is for upload. Turn it off to keep the original file. Other image formats stay unchanged. Staff profile photos always keep the original file and remain subject to the profile photo size and dimension limits.

The image keeps its ID, name, alt text, credit and usage, along with its other saved metadata. The new file gets a new URL and version. The old file goes to the purge queue with a 30-day hold; replacement does not delete it immediately. After success, the library refreshes the thumbnail and version and reminds you to check the alt text for the new image. Selecting the current file leaves the image unchanged.

Published or deployed usage blocks replacement. Republish the affected page without the image, or unpublish it, before replacing the file. For a stale version, choose **Reload asset** before choosing and confirming the file again. File type, staff profile and capacity refusals show the server's explanation. A recovery or lock refusal asks you to try again later.

If the replacement matches a file that cannot be found in the active library, the message says it may be in the Recycle bin. Staff with bin access can choose **Find it in the Recycle bin** to look for that image, with their Images filters preserved. Other staff see **Ask a media manager to restore it**. The replacement dialog closes after the lookup finishes, before you follow the link.
